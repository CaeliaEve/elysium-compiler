# BetterQuesting declarations

Source 40 / Catalog 39 represent `bq_standard.integration.nei.QuestRecipeHandler` as a nonconsuming reference domain, not a recipe. The installed BetterQuesting 3.7.15-GTNH implementation is authoritative; its NEI positioned stacks lose native task/reward distinctions and cap displayed cells at sixteen.

`questsDefinition` records readiness, source ownership, complete registered UUIDs, visible UUIDs in native order, world policies, and actual declaration/fact counts. `questDeclaration` preserves each visible quest's stable UUID, raw and translated text with native translation keys, prerequisites, native policies, ordered task/reward storage IDs, and typed callback rules. Hidden quest contents and player progress/history are not serialized.

Visibility is `QuestCache.isQuestShown` for the current native questing player. Export requires a loaded single-player world/player cache, Forge AVAILABLE, BetterQuesting world directory and initialized API bindings. It does not claim multiplayer completeness. A known-ready empty database is legal; absent initialization is an explicit failure. A hidden prerequisite differs from an absent UUID. The Compiler verifies both against the complete registry and visibility proof. Native main-quest status, edit mode, hardcore policy and configured default/maximum lives are retained; current player lives/progress are not. GUI backgrounds, placement offsets and sound effects are deliberately outside this semantic domain.

Thirteen standard task owners are supported: retrieval, optional retrieval, crafting, fluid, meeting, hunt, item interaction, entity interaction, checkbox, location, XP, block breaking, and scoreboard. Six reward owners are supported: item, choice, XP, command, scoreboard, and quest completion. Owner, factory ID, and label key must agree with the typed rule. Unknown/custom task, reward, or quest classes fail explicitly.

Item declarations retain signed native amounts, base patterns, ore availability/key and ordered candidate patterns. Patterns retain metadata, typed NBT, native damageability and concrete display examples. A wildcard remains a wildcard; its native subtype samples do not become an exhaustive gameplay matcher. Native base OR ore matching and damageable metadata handling are retained. Optional retrieval is excluded from mandatory task logic. Rewards grant the native base stack, split by stack limit; choice selects one reward entry. Raw nonpositive counts remain visible, alongside the native `max(1, amount)` grant policy. No detect, submit, claim, GUI drawing or progress-serialization callback runs.

Task scoreboard conversion preserves exact IEEE float bits. Reward scoreboard criteria read the live `type` field, because installed `writeToNBT` always writes `dummy`. Location `hideInfo` and command `hideCmd` are declared and honored by the UI; no command executes from the webpage. Quest text uses native UUID-based URL-safe Base64 keys and actual translation callbacks.

Capture has bounds on native lists, total repeated declaration traversal, fact counts, each Source record, and total declaration bytes. It fails rather than truncate. Periodic verification checks readiness/registry size; sealing rechecks the complete declaration, visibility, policy, text and specimen signature. No past `writing` archive is reclassified as complete.

NeoNEI's shared `/quests` query is identical online and in its offline worker. A bounded index preserves native order, search/UUID/item filtering and paging. Only current-page related facts are hydrated; icons and rule details mount when expanded. The reader checks schemas, leaf hashes, native source, visibility proof, task/reward owners, prerequisite states and actual specimen references. Tasks, optional submissions and rewards have separate sections, with material/candidate paging beyond the old sixteen-cell GUI limit. The page has no recipe GUI views or progress tracks.

Local conformance uses actual installed constructors/fields and visibility/rule callbacks with controlled registries. The route test isolates only the native handler's unused font-height class initializer. These fixtures and stopped-backend offline browser checks do not establish full-pack quest registration, English coverage, renderer fidelity or live-game acceptance. Those checks belong to the later Export Agent batch.
