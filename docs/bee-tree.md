# BBAB native bee tree reference

`hellfirepvp.beebetteratbees.client.gui.BBABGuiRecipeTreeHandler` accepts item-context queries, not a full overlay recipe enumeration. Its slots are an illustration of ancestry, not consuming ingredients. The dedicated Java reference reads its initialized `speciesRoot` and the native `getMutations(false)` list without creating or drawing a recipe GUI. An uninitialized root is an error; an initialized empty mutation list is a legal one-definition reference.

The record set contains a definition, sorted species specimens and every mutation in registration order. Duplicate registrations remain separate. A mutation retains its ordered parents, result, full result-template allele UIDs (including null chromosomes), reduced fractional base probability, exact native condition descriptions and secret eligibility. It does not execute housing-dependent mutation conditions or claim an effective chance for the current world. Exceptions from condition callbacks propagate instead of inheriting the native GUI's swallowed exceptions.

Species specimens use the installed BBAB `createStack` callback: the root's default template is converted to an individual, analyzed, and represented as princess (1) or drone (0). These default-template specimens are distinct from the mutation's result genome. Native NBT and item identities are retained; item animations continue through the content renderer.

The native display uses the first registered mutation for each result, including unfiltered secret routes in ancestry. Root eligibility separately respects `shouldShowSecretRecipes`. The native tree is built to depth 4, duplicate branches are pruned according to `showDuplicateTrees`, and visible ancestry ends at depth 3. NeoNEI represents this relationship with its own components, retains precise chances and conditions, and also offers all eligible registered routes without adding their chances together. It does not capture GUI lines, backgrounds, pixel coordinates, progress or decorative textures.

Compiler validates the typed graph, source binding, complete counts and order, species/member closure, result genome, fractions and secret policy. Express and the offline worker use the same bounded lazy query; only current route/ancestry specimens are hydrated. The client rejects missing member facts and inconsistent route visibility. A bounded ancestry traversal handles cycles and repeated species.

Local verification invokes the actual installed remapped BBAB helper with a controlled Forestry API registry and registered vanilla paper specimens. It proves helper/analyze behavior, routing away from the consuming template, duplicate registration, fractional chance, condition-error propagation and ready empty lists. Java records pass the complete Compiler domain gate and shared Node query. A real compiled Catalog passes one online and stopped-backend persistent-browser offline journey, including hard reload, native condition formatting, item navigation, contrast and footer visibility checks.

The fixture does not prove actual installed bee registrations, renderer pixels, every custom mutation callback, server synchronization or full-pack language/coverage/performance. Those remain for the Export Agent. New frontend builds are independent test artifacts and do not replace the active preview. This module is part of the still-incomplete three-project implementation goal.
