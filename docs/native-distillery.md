# Witchery distillery native inventory law

The pinned Witchery 0.24.1 producer reads native DistilleryRecipe fields and WitcheryExtras 1.3.8 registration roles without constructing NEI CachedRecipe or PositionStack objects. Its source cursor binds native source/list/member/array/stack/NBT identities, metadata predicates and the jar role. Ready-empty and missing sources are separate states. Only owned snapshots are captured; full membership is checked at sealing.

`process:witcheryDistillery` owns two swappable reagent positions, required null positions, the signed jar count and prior native recipes. Reagent matching ignores stored count and NBT; metadata is exact only for native subtype items. Native registration order wins before output-capacity evaluation. Jar insertion admits clay jars, but the native runtime matcher checks only presence/count, including preloaded non-jar inventory. The shown clay jar is an admission witness, not an exact runtime identity restriction.

Every occupied reagent slot loses one item. The jar stack loses the signed native count, so negative values add items and native signed arithmetic can overflow. Zero requires no jar stack. Neither path returns crafting containers. Both-null reagent definitions are explicitly unreachable through getActiveRecipe; sink recipes with nonempty reagents and no outputs remain legitimate.

There are four independent output slots. Zero or negative prototype counts remain signed inventory mutations in the process and do not become positive recipe outputs; the frontend labels them explicitly. Empty slots copy prototypes. Matching item/meta slots merge and retain existing NBT. A mismatched output does not block processing: placement skips that slot while inputs and jars still debit. Only matching occupied output slots perform signed-addition capacity checks against the inventory and item limits. Therefore every output is a potential inventory result, not a guaranteed fixed tagged stack.

Work requires800 successful altar-power ticks at the native float0.6 bit pattern3f19999a. Missing power pauses progress; an invalid recipe or blocked output resets it. A recipe change that remains processable can carry accumulated progress. These are work ticks, not an unconditional wall-clock duration or EU/t cost. The native inventory operations and matching were exercised locally; the updateEntity power/world path is also grounded in pinned bytecode, not described as a full live-world run.

Source40/Catalog39 development contracts semantic.59 add the process and distilleryJar predicate. Actual Java transport IDs are checked before complete domain validation. The shared query hydrates all prior reagent references and the canonical jar even when no visible jar input exists. Dedicated frontend layouts retain both reagent positions and all four independent output positions.
