# Witching Gadgets spinning process

`witchingSpinning` is the dedicated process for
`witchinggadgets.client.nei.NEISpinningWheelHandler` in 1.7.25-GTNH.
The new variant is pending the unified contracts release and local verification.

`definitions` keeps native registration order. Each definition has a nullable
`inputs` array whose entries distinguish direct stack selectors, ArrayList
selectors and requirements which never match. Selectors compare registry and
template metadata, with 32767 as a wildcard and no NBT/count predicate. The
selector packs the five physical occupied slots and requires equal cardinality.
Direct stack matches remove and break; list matches remove and continue. Its
hit flag persists across offered stacks. A generic shapeless assignment is not
equivalent to this law.

The selected recipe keeps one-item consumption for each occupied input example,
without crafting containers. Actual native completion decrements all occupied
input slots, including unmatched offers accepted by the native matcher. The
fixed result is an empty-output-slot prototype, conditional on native selection
and output stock. Therefore material planning must not promise unconditional
batch output. Existing stock merges by item/metadata, preserving its own NBT
and applying both stacks' native limits.

The process has no fixed elapsed duration: default progress from zero takes 121
consecutive valid work calls, while actual progress/maxProgress and output
inventory remain world state. A displayed candidate tuple can be claimed by an
earlier registration; consumers must run the full selector and hide an invalid
selected output. Typed validation rejects stripping this process from its
native Handler or weakening its predicates/consumption. Native recipe GUI
assets and progress tracks are not part of this contract.
