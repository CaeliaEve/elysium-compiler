# Headless recipe content (development Source 41 / Catalog 41)

Recipe and category `notes` contain bounded native explanatory text references.
Each entry has a stable namespaced `key`, a nonempty native reader `source`, and
a `text` string identity. Keys are unique within an owner, at most 256 bytes;
there are at most 256 notes per owner. Source labels are at most 512 bytes and
contain no control characters. Native rules still belong to typed process or
property fields. Notes do not change recipe identity. These are display-text
bindings, not evidence that every native Handler's explanatory text is covered.

The current Source and Catalog have no `views` or `tracks` collections and no
recipe/category `view` field, including null placeholders. Rust and the generated
consumer decoder reject these retired shapes. Exporters write explanations
directly as notes; the Compiler does not OCR screenshots or infer instructions.

Native grids, slots, candidate correlations and typed process laws remain domain
facts. Assets, inventory visual programs, research illustrations, model faces and
content animation frames retain their existing transport and validation.
Publication never rewrites Source bytes or historical manifests.

The shared query hydrates explicit notes and content textures without any GUI
table reads. The current mainline reads only its current revision. Historical
Catalogs remain unchanged and require their matching archived reader or a fresh
download; there is no online legacy conversion.

Development fixtures were migrated once, preserving their existing text as notes
before removing GUI records. This is not native recapture. Native Handler
information coverage, localization and final exact-instance release gates remain
separate acceptance work. No replacement recipe page is provided.
