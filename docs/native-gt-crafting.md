# Installed GT crafting observations

Source 40 / Catalog 39 and contracts `0.40.0-semantic.36` add the explicit
`gtCrafting` process/action for installed GT 5.09.51.482. Only native NEI
shaped/shapeless handlers own it. GUI views/tracks are not involved.

The process contains exact ordered declarations (including duplicate signed
enchantments and unused trailing levels), the parent prototype, first normalized
base, simulated input-discharge observations, and one actual result witness per
distinct native result state. Output samples are index-aligned with witnesses;
they are neither single-input transforms nor a Cartesian input tuple table.

Compiler reconstructs bounded matching/state coverage from actual input facts:
keeping-NBT uses native tag equality; shapeless allocation uses first remaining
matching requirement; first inherited/overwrite tag identities remain lossless;
electric transfer wraps as a signed Java int. Shaped positions must preserve the
logical grid, translation and allowed mirroring. Shapeless coverage uses subsets
of offered input slots, not enumeration of all permutations. Missing/duplicate
states, bad positions/counts, unknown process versions and changed scope fail.

The finite domain has at most 65536 candidates/states and 8388608 transitions per
placement search. The reader also limits combined captured placement cases.
Native callback result values are observations from NESQL++'s audited owned
pipeline and native comparison; Compiler does not execute Java or independently
replay every GT normalization/electric callback. The explicit
`scope: exportedCandidates` does not promise arbitrary inventory/NBT evaluation.
Rules still describe how arbitrary player tags/count/charge can change results.

NeoNEI uses current selected candidates and offered order, supports native
mirroring/reordering, and suppresses outputs for a nonmatching combination.
Material totals keep the result conditional. API related records include both
prototype/base and every observed result so offline selection has its closure.

These are local conformance capabilities. Live registry counts, native pixels,
complete bilingual content, whole-pack acceptance and unified release remain
separate required evidence.
