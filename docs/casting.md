# ExtraUtilities casting effects

Source 36 / Catalog 35 supports `process: {kind: "unstableCasting"}` on TConstruct casting-table recipes. The item output is a **prototype**, with the runtime changes below; it must not be interpreted as a fixed final NBT identity. Input quantities, mould consumption, fluid consumption and cooling time retain the usual casting semantics.

The exporter audits the exact registered ASM callbacks from ExtraUtilities 1.2.12. `addBedrockiumPartSlowness` runs on an owned output and retains its native AttributeModifiers list, UUID and -0.1 movement-speed operation. Inert branches remain inert. Unknown listener classes, callback methods or tool-part material predicates fail explicitly.

For an output whose native tool material equals the positive configured unstable material ID, `addUnstableTimer` first ensures a root compound. The exported prototype retains that compound and all existing fields. The exporter does not read server clocks or store an export-time timestamp. At native completion, if overworld 0 is loaded, the callback sets root long `XUDeadline` to its total world time. If the world selected by the listener's most recent server START WorldTickEvent is also loaded, it sets long `XULocalDeadline` to that world's total time and int `XULocalDim` to that dimension. Missing worlds leave those fields unchanged. These conditional overwrites are the meaning of `unstableCasting`; they are not a probabilistic yield or a fixed crafting transform from the mould.

The native expiration check uses `overworld.totalTime - XUDeadline > 200` and applies only when the part has the configured unstable material and a long deadline tag. Tool assembly/expiration is a later native interaction, not another static casting output. This contract reports that limitation without inventing a completed tool recipe. The web uses the existing conditions panel to show that the output has runtime timer NBT; its layout and effects are unchanged.
