# Native processor contracts under development

Development NESQL 0.45.0-semantic.2, Compiler/contracts 0.40.0-semantic.2, Source 40 and Catalog 40 explicitly
version the additional native machine rules. This is a development contract,
not a record of completed live acceptance for all registered handlers.

HarvestCraft records one shared `harvestDrops` process. Gardens draw uniformly
with replacement; traps select one entire stack using integer weights. The
`harvest` quantity is a per-selection nominal count and cannot be summed as
independent guaranteed output.

Blood Magic altar records whole-stack conversion, native tier, LP and upgrades,
tag-presence matching, and all earlier registry predicates, including entries
without visible results. `bloodAltar` is a single-item preview count; Java int
multiplication and machine state determine whole-stack results. Binding retains
the owner soul network, activation/event/structure gates and entity cooldown.
Meteor retains correlated spatial placement, reagent and native callback rules.

Forestry Bottler keeps fixed-container and Forge/IC2 dynamic fill callbacks
separate. Partial fill replaces the input and need not produce an output item.
Fabricator uses a shared rule context containing crafting and smelting sections;
the compiler checks plan wear, stock allocation, shifted/mirrored grids, liquid
requirements and summary rows against that context.

Binnie Lumbermill keeps the first ore-name admission and native registry
priority. Planks must fit; bark and sawdust are best-effort insertions. Its water
input is an internal stock gate with repeated partial drains, not a fixed
per-recipe volume or a buffer emptied at startup. Actual native tests observed
31 updates for first work and 30 for a queued continuation; stalls remain dynamic.

Java-generated small contract fixtures are replayed through full compiler domain
validation and semantic mutation rejection. They verify these native examples
without replacing exhaustive runtime diagnostics, representative GL rendering,
Source sealing, dual-path compilation or online/offline Web acceptance.
Historical acceptance reports and incomplete `writing` archives stay unchanged.
